# 台灣公民科技與開放資料：怎麼用資料客觀究責一個地方政府

來源：一場對話從「台灣政治視覺化有哪些有趣專案」的資源盤點，逐步被追問到「新竹市長高虹安這任期到底做了什麼、怎麼客觀評估」，最後產出一個實際的互動網頁案例（[新竹市長支票簿](https://claude.ai/code/artifact/1e9c9c02-5aa4-48bb-9408-d8dacb1c76ab)，Artifact）。

## 一句話

客觀究責不是「找一個資料源」，是把政府自己的話、監督者的話、硬數字、時間軸分開放，讀者自己比對——查不到數據時要老實寫出來，不能假裝沒這回事。

## 台灣公民科技生態系（資源盤點）

- **g0v 零時政府**——社群母體，10 幾年 850+ 專案，「用開放資料視覺化幫公民看懂政府」是核心方法論
- **READr / 報導者**——資料新聞取徑，政治獻金 12 年政商關係視覺化是代表作
- **窩窩（vote.wuo-wuo.com）**——單一議題（動物保護）逐項候選人政見兌現度分析，方法論最扎實：政見原文｜執行情形｜佐證資料三欄式，兌現/部分兌現/跳票未見執行/無政見可考四級標籤，金字塔式資訊架構（摘要→總覽表→個案→議題分析→方法論揭露）。**這是本次做支票簿最直接參考的範本**
- **沃草・國會無雙**——立委問政表現評分（好球/烏龍球/界外球），2013 年老牌
- **iVoter**——議題立場配對測驗，讓選民找出跟自己立場最近的候選人
- **政治獻金視覺化系列**——政治獻金與牠們的產地（縣市地圖）、前金後謝調查局（個人專案，2.8 萬家公司獻金追蹤）。這條取徑答的是「錢跟誰有關係」，跟政見兌現追蹤（做了什麼）是互補但不同的究責角度，還沒深入比較兩者優劣
- **g0v ly.govapi.tw**——把立法院分散資料整理成 API，是少數真的有可查詢 API 的案例。多數縣市開放資料平台只是逐筆下載

## 客觀究責一個政治人物，要拆五層（核心方法論）

實作「支票簿」的過程中，從單純政見兌現表演化成五層架構，理由是這五種資料性質不同、混著比會導出錯誤結論：

1. **接手時 vs 現在的硬資料**——最接近客觀（如新竹市公共債務 100.17 億元→0），但「誰的功勞」仍可能有爭議
2. **政見原文對照執行現況**——要先看政見當初是口號還是具體承諾，模糊口號沒辦法判定兌現
3. **客觀事件時間軸**——法院判決、政黨決議、政府公告，最不受詮釋影響，因為每個節點都有官方紀錄可查
4. **各方各自的說法**——市府 vs 監督者，本身是政治攻防的一部分，只能並陳不能仲裁
5. **民調/滿意度**——反映觀感不是做了什麼，且同一個人選在不同民調公司/委託方/問法下數字可以差很多，不該跟前四層放同一個天秤

## 三個具體發現（可能可重用）

**政府開放資料平台的分類常是生命事件導覽，不是主題分類**：新竹市開放資料平台的「18 個分類群組」實測是「生育保健/出生及收養/求學及進修」這種公部門服務生命週期分類，不是資料主題分類。要找真正有監督價值的資料，得改用「組織分類」（依發布機關瀏覽）——例如主計處(27筆)/財政處(53筆)大概率有決算數字，工務處(13)/養護工程處(36)有工程進度。平台本身多是客製化 ASP.NET，逐筆下載，沒有 CKAN 那種批次查詢 API（試過標準 CKAN API 路徑，404）。

**公辦工程跟自辦工程的課責邏輯不同，但政府公關語言常不區分**：新竹案例裡，市府直接主責的「公辦重劃」（中油油庫案，停滯 32 年後她上任滿月啟動，後來得國家獎）跟地主自組、市府只負責查核的「自辦重劃」（光埔案，重劃會承諾封路 3 個月變 1 年半+），課責對象完全不同。但市府對外都用「整體進度 75%」這類總體數字溝通，容易蓋掉受影響居民的實際感受。監督時要先分清楚「誰簽字負責」。

**找不到官方逐年可比的城市級數據，本身就是一種監督發現**：查新竹市交通壅塞「2022 vs 2026」量化對照時，TomTom 指數、事故統計、交通部道安網都沒能給出市府自己逐年公布、口徑一致的數字——連唯一查到的「智慧交控改善 30% 行車時間」都是隔壁新竹**縣**政府的成果，容易被誤植成市府政績。一個城市在市民票選最優先關心的議題（交通，一份議員問卷測出 6 成市民列第一）上連基本追蹤數據都沒公開，這件事本身值得記一筆——但也要留意：「查無資料」不等於「資料不存在」，可能只是沒窮盡管道（例如該用政府資訊公開法正式函文，而不是只找開放資料平台）。

## 我在查證中段修正自己的一次錯誤

市府任內最後施政報告主打「零負債」，但我一開始把議員相挺說法「政見落實率破 8 成」誤植成「債務清償率 83%」——直到查到 2026-07-15 官方零負債公告的具體數字（100.17 億→0，100% 清償），才發現這兩個說法口徑根本不同（一個是政見整體落實率，一個從沒明確說是債務）。**同一個陣營的說法都可能因為引用的指標/時間點不同而互相矛盾，查證要回到原始數字，不能停在任何一方（包括自己第一輪）的摘要。** 這條跟這個 repo 既有的「篩子第四格：一手 vs 轉述」是同一個病的第四次發作（EU AI Act／SanDisk 財報／skill 規格主詞／這次），只是這次連「自己一開始的整理」都要重新對照原始來源才抓到。

## 還沒深入的

- 政治獻金視覺化 vs 政見兌現追蹤，兩種究責取徑該怎麼結合
- 「配票」（同黨候選人依身分證尾數建議支持不同號次）這個台灣特有現象，沒查到專門做視覺化的專案，是個可能的空白
- 五層方法論能不能套用到其他縣市首長，還是新竹這個案例剛好資料特別齊全（零負債公告、棒球場醜聞、輕軌卡關都是現成媒體熱點）——需要再拿一個縣市驗證才知道
